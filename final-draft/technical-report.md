## Introduction
As trends and weird events happen on the internet, it can be difficult to keep up with the rapid pace of culture. Fortunately, internet users can help give us insights into what is happening and what pieces of content are similar. This paper will go over an example of this using Wikipedia click data within the month of October, 2025. All of this data is based solely on the click behavior of users on Wikipedia.

## What Problem can this Technology Solve?
With the rapid pace of the internet, it can be difficult to group similar content together or to be able to tell what genre a new item should be. Sure there are the labels that the creator placed on their creation, but these need to be taken with a grain of salt. These labels can carry human biases or even purposefully be mislabeled to benifit specific parties. Instead, it would be much better for users and companies, at least if there are no nefarious intents, to use naturally occuring data to decide what to do with new items. In this way, it can be a large group of users and their habits that describes an item, rather than a single person's concious thought. There are a few ways to do this, but something than many companies should have available is data to tell where a user went from one page or piece of content to the next. This can be used by the Leiden Community Algorithm.

## The Basics of the Design and What Would Be Required
Using grouping algorithms, such as the Leiden Community Algorithm used in this project, natural grouping and behaviors can be discovered, while keeping biases to a minimum. By simply saving data about what users clicked on and from what page they clicked to that, this algorithm can be implemented into many systems. Feeding this data into the algorithm will immediately start producing results. Out of it, the implementer would get groupings of content that the users themselves are making. This could be utilized for a page by page recommendation system or a way to generate user personas. For the recommendation system, it could be that a page with the most popular content in the same cluster as the current page is presented to the end user. This would allow users to more quickly get to pages they would be intersted in without clicking through multiple pages or maybe not even finding an interesting article. To build user personas, vectors could start to be built off of how much time a user spends within each community, how many articles they click to within a community, etc.. 

## Specifics of this Implementation
This project utilized the publicly available information at [Wikipedia Dumps](https://dumps.wikimedia.org/other/clickstream/readme.html). From this algorithm, many clear, sensible clustering were produced. The clusterings of articles titles were also fed into a Large Language Model to give some working titles of each cluster. From a random sampling there were groups like Prix / Grand / Formula that contained many articles on racing, racecar drivers, and cars, more specifically titles like 'Charles Leclerc', '2025 Azerbaijan Grand Prix', and 'McLaren 650s', Artificial / Intelligence / Learning that contained many topics on machine learning, artificial intelligence, and systems that can interact with the real world, like 'IWarp' (a protocol used in large datacenters, much like what AI's need to run), 'Neural Clique' (units of memory in humans, which some scientists are trying to synthesize for AI), and 'Neuromorphic Olfaction Systems' (artificial noses for machines). There are hundreds, even thousands, more of these examples that the community detection algorithm was able to pick up just by how people clicked. The kernel that was used in the Leiden Community Detection algorithm was one called CPMVertex, which gave granular enough results, without cutting down some obvious clusters into nothingness. Something that implementers should be cautious of when using this is that the tuning of the resolution parameter can lead to some very different results. For example, when using a higher resolution parameter, a very random housing development was included in a cluster that mostly contained Marvel superheroes and characters. Something else that needs to be taking into consideration is the structure of the platform itself. An issue that I was running into was the Wikipedia disambiguation pages, which are pages that simply sort out similar sounding article titles. This could be something like moon (celestial body orbiting earth), moon (rude action), and moon (character from Transformers). These pages tended to help cluster together unrelated articles, simply becuase people would land on these pages, then split off into whatever specific page they wanted. This same phenomena could happen on a social media page that has creator's pages with all of their content.
